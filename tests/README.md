# Tests and checks

This directory holds the test records of each phase and the scripts that check them. This page covers:

- the checks that run offline, and what each one prints;
- which scripts write into the working tree;
- which scripts must not be run.

Everything below was verified on 2026-10-30 on Linux with Python 3.13.17, running from the repository root.

- The checks use only the Python standard library and git.
- They need no network access and make no model calls.
- Commands are written `python3`; on other systems, use your own interpreter's name.

## What is here

| Path | Contents |
|---|---|
| `phase2/` | Phase 2 test cells, rater scores and reconciliations, and the R1 compression scripts (`r1_compressor.py`, `r1_normalizer.py`, `r1_ab/`) |
| `v0.2/` | The v0.2 expansion: prompts, corpus cells (`cells/`), rater tables and statistics (`scoring/`), and the pipeline scripts (`_*.py`) |
| `unit/` | Unit tests for `_stats.py` and the R1 scripts |
| `cross_llm/`, `usability/`, `test_plan.md` | Records only; nothing to run |
| `run_checks.py` | Runs every offline check below |

## Run everything: `run_checks.py`

```
python3 tests/run_checks.py             # summary
python3 tests/run_checks.py --verbose   # also each step's output and the known diff
python3 tests/run_checks.py --keep      # keep the temporary copy and print its path
```

- [FACT] The runner works in a temporary copy, never in the working tree ([run_checks.py](run_checks.py), docstring):
  1. It copies the files git lists as tracked or untracked to a temporary directory. Ignored files, such as `v0.2/cells/_cycle_secret.txt`, are not copied.
  2. It runs the seven commands of the next section in that copy.
  3. It compares the copy with the working tree.

  It writes nothing in the working tree or in `.git`.
- [FACT] A step passes when it exits with status 0.
- [FACT] The last three steps regenerate committed files.
  - Each of those files is deleted from the copy first, so the step must write it again.
  - It must then match the working tree byte for byte, or after converting CRLF to LF.
  - Any other changed, missing or new file fails the run.
  - One file, `_ratification.md`, is accepted with a known difference; see *The `_ratification.md` difference* below.
- [FACT] Exit status 0 means every check passed; 1 means at least one failed.

Output on 2026-10-30, without the first two lines, which name the repository and the interpreter:

- the commit shown for `origin/main` is the one in your clone;
- the file count grows with the tree.


## Unit tests

[FACT] `unit/` holds two files:

- [test_stats_numerics.py](unit/test_stats_numerics.py) checks the pure functions of `_stats.py` against references computed independently of them. The functions are the Student's t p-value, the regularized incomplete beta, the quadratic-weighted kappa and the paired deltas. It never calls `main()`, so it runs no `git show` and rewrites nothing.
- [test_r1_roundtrip.py](unit/test_r1_roundtrip.py) checks that `normalize(compress(text)) == text` for the R1 compressor and normalizer. It runs on two inputs:
  - the committed MAB-1..5 cells, where the result is exact;
  - 4,000 seeded random texts.

Three tests are marked `@unittest.expectedFailure`. Each documents a defect that is reported, not fixed; changing scoring or R1 code is the owner's decision.

| Test | Defect | Effect on committed results |
|---|---|---|
| `StudentTTest.test_matches_exact_values_near_zero` ([test_stats_numerics.py:129-150](unit/test_stats_numerics.py#L129-L150)) | For \|t\| near 0, `student_t_two_sided()` returns p-values far below the exact ones. Example: df = 28 and t = 1e-4 give 0.0077 instead of 0.9999 | None. Take the \|t\| values in the committed `_test_b_delta.md` (0, 0.2386 and 0.3723, with df = 28). There, `test_matches_exact_values_away_from_zero` checks that the function matches the exact values to within 1e-9 |
| `KnownP3GapsTest.test_stacked_marker_inside_a_run` ([test_r1_roundtrip.py:130-146](unit/test_r1_roundtrip.py#L130-L146)) | In a P3 run of three or more lines, a stacked third marker comes back with an extra space: `[FACT][CONF(medium)] [NOSRC] b.` | None. MAB-1..5 contain no run that P3 compresses, and `CommittedCorpusTest` reproduces them exactly |
| `KnownP3GapsTest.test_marker_only_lines_inside_a_run` ([test_r1_roundtrip.py:148-157](unit/test_r1_roundtrip.py#L148-L157)) | A P3 run of three or more marker-only lines, with no claim text, is dropped | None, for the same reason |

[FACT] Once a defect is fixed, its test passes. Until its decorator is removed, the run then ends with `FAILED (unexpected successes=1)` and exit status 1 (checked with Python 3.13).

## `_stats.py` reads `origin/main`

- [FACT] `_stats.py` reads its two input tables, `EpistemicLogician_scores_unsealed.tsv` and `IndependentRater_scores_unsealed.tsv`, with `git show origin/main:<path>` ([_stats.py:37-43](v0.2/scoring/_stats.py#L37-L43), [:218-219](v0.2/scoring/_stats.py#L218-L219)).
  - It does not read them from the working tree.
  - It does not read them at `PIN_COMMIT = '0d67287'` ([:28](v0.2/scoring/_stats.py#L28)). That value only appears in the generated text.
- [FACT] It therefore needs a clone with an `origin/main` ref (`git fetch origin main`). Without one, `git show` fails.
- [FACT] If those tables ever change on `main`, `_stats.py` produces different figures, with no change in the working tree.
- [FACT] To guard against this, `run_checks.py` first checks that both tables are identical at `origin/main` and at `PIN_COMMIT`. It fails without running the script if they differ or if either commit is missing. A shallow clone may need `git fetch --unshallow origin`.

## The `_ratification.md` difference

- [FACT] `_stats.py` reproduces the committed `_kappa.md` and `_test_b_delta.md` byte for byte, but not `_ratification.md`.
- [FACT] The two files give different verdicts:
  - The committed file gives `**§3.1 + §3.2 verdict (F2-scoped): INCONCLUSIVE** (with strict-reading FAIL noted as alternate).` ([_ratification.md:27](v0.2/scoring/_ratification.md#L27)). It sets out two readings of the D1 kappa gate, with κ = 0.3729 and 95% CI [0.1132, 0.6177] (lines 10-13 and 29-33).
  - The regenerated file gives `**§3.1 + §3.2 verdict (F2-scoped): FAIL**`.
- [FACT] The committed file asks for a RedTeam audit and CEO ratification to pin the canonical reading ([line 31](v0.2/scoring/_ratification.md#L31)).
- [UNCERTAIN] This repository records no such ruling. It also does not say why the committed text differs from the script's output. Both files last changed in `28f4ae6` (2026-05-10).
- [REC] Keep the committed file unchanged until that ruling, and never commit a regenerated `_ratification.md`.
- [FACT] `run_checks.py` accepts the difference only as this exact pair of contents, identified by their sha256 in `KNOWN_DIFFERENCES`. It fails on any other content.
- [REC] When a ruling changes the committed file, update or remove that entry. The runner prints a note when the entry is no longer needed.
