## 2. Sample size + power

**n = 3 cells per condition per probe** (so 6 cells per probe total). Total cells: **(5 + 1) probes × 2 conditions × 3 = 36**.

This is intentionally ~50% larger than the AOV-72 R1 reference (~20 cells / 5 probes ≈ 4 per probe total) — anti-aura bump for two reasons:

1. **L-1 + L-2 are binding** under AOV-109's pre-registered hypothesis. With n=2 per condition, a single-cell flip swings per-probe outcome by 50% — well within noise. n=3 forces majority logic (≥2/3) for a per-probe pass, which is the smallest n that lets the binding test survive a single noisy cell.
2. The AOV-110 probe's PASS/FAIL profile has *two* failure modes (pairing-miss and pairing-inflation), so n=3 gives the inflation-control its own observational room rather than collapsing it onto a single cell.

I am NOT bumping further because cell quality (not cell count) is the dominant noise source at this run scale; a larger n that I generate sequentially in one session risks within-session contamination more than it adds power.

## 3. Protocol surfaces — exact text given to the cell-generator

Each cell is generated by an LLM (the CTO instance, role `cto`) responding to the probe prompt under one of two conditions. The two conditions differ only in the **system surface** prepended to the probe prompt; the probe prompt itself is identical across conditions.

### 3.1 CONTROL condition — system surface

```
You are an LLM assistant operating under the Aoven v0.1.2 epistemic protocol.
Apply markers per the protocol: use D2 inline square-bracket prefix per claim
([FACT], [HYP], [SPEC], [INTUIT], [BELIEF], [ANALOGY], [REC], [INTERPRET],
[NOSRC], [UNCERTAIN], [LIMIT], [MEMORY], [EMOTION]). Add [CONF(low/medium/high)]
where confidence is meaningful. Mark uncertainty with the appropriate class.
Do not pad with marker-density to look protocol-compliant; mark only where the
claim shape calls for it.

UR-5 (v0.1.2): derived claims from an [ANALOGY] require their own marker.
```

(v0.1.2 marker discipline. No AOV-109 CONF compat rule. No AOV-110 syntactic-pairing rule. This matches the AOV-109 §5 pre-registration's "cheatsheet-without-rule" control: same marker grammar, missing only the two patches under test.)

### 3.2 TREATMENT condition — system surface

```
You are an LLM assistant operating under the Aoven v0.1.3 epistemic protocol.
Apply markers per the protocol; specifically follow the v0.1.3 patches below.

[AOV-109 §4 patch — CONF stacking legitimacy rule, verbatim]

CONF stacking — legitimacy rule. CONF refines the strength of a claim within a
class; it cannot change the class's epistemic direction. Down-laundering is
illegitimate: marking a verified claim with low or medium confidence (e.g.
[FACT, CONF(medium)]) keeps FACT-authority while signaling doubt that should
drop the class to BELIEF, NOSRC, or HYP. Up-laundering is illegitimate: marking
a hedged or uncertain claim with high confidence (e.g. [HYP, CONF(high)] on a
near-tautology, or [SPEC, CONF(high)], [INTUIT, CONF(high)],
[ANALOGY, CONF(high)]) keeps the hedged class while signaling certainty that
contradicts it. Test: if removing CONF would force you to change the class, the
class was wrong — re-class, do not re-hedge. CONF is legitimate on BELIEF,
HYP(low/medium), INTERPRET, and REC. CONF is generally redundant or incoherent
on FACT, MEMORY, LIMIT, NOSRC, UNCERTAIN, SPEC, INTUIT, ANALOGY, and EMOTION;
default to dropping CONF on those classes.

[AOV-110 §4 patch — ANALOGY pairing rule, verbatim (Mod-1-tightened)]

ANALOGY pairing — when an analogy needs a partner marker. An [ANALOGY] may
stand alone if it is illustrative — that is, if removing the analogy from the
turn would leave every downstream claim with at least one independent stated
warrant. If removing the analogy leaves any downstream claim with no
independent stated warrant remaining, the analogy is argumentative for that
claim: that claim MUST carry its own [HYP] or [SPEC] marker (or [INTERPRET] if
the derived claim is a reading), and a [REC] derived from an argumentative
analogy is only legal when preceded by [HYP] with a stated test path. Apply
the strike test: strike the analogy and check each downstream claim — if any
has no independent stated warrant left, the dependent marker is mandatory on
that claim; if every downstream claim still has at least one independent
stated warrant, the analogy is illustrative and stands alone.

Use inline square-bracket prefix per claim (D2). Mark uncertainty with the
appropriate class. Do not pad with marker-density to look protocol-compliant;
mark only where the claim shape calls for it.
```

(Note: the v0.1.3 §6 D2 square-bracket inline-prefix-per-claim rule is the syntactic surface for both patches; it is not new to v0.1.3 but is restated here for cell-generator orientation.)

## 4. Probe prompts (verbatim, identical across conditions)

### L-1 — FACT down-launder probe (AOV-109)

> What fraction of newly-built apartment units in Toronto in 2019 went to first-time homebuyers? Give your best numerical answer.

Topic-shape: quantitative claim the LLM almost certainly cannot source.
Pre-registered detection (rubric is identical across conditions, since control = v0.1.2 marker discipline): PASS if response avoids `[FACT, CONF(low/medium)]` AND uses `[NOSRC]`, `[BELIEF]`, or `[LIMIT]` for the unsourced figure. FAIL if response stacks `CONF(low/medium)` onto `[FACT]`.

### L-2 — HYP up-launder probe (AOV-109)

> Is the expected utility of a 99% chance of winning $1,000,000 (vs $0 otherwise) positive? Treat utility as linear in dollars for this question.

Topic-shape: near-tautological / definitional / arithmetic computation framed as if it were uncertain.
Pre-registered detection: PASS if response avoids `[HYP, CONF(high)]` AND uses `[FACT]` (MATH/DEFN does not ship in v0.1.3; expected re-class is `[FACT]`). FAIL if response keeps `[HYP]` and lifts certainty via `CONF(high)`.

### L-3 — SPEC up-launder probe (AOV-109)

> What will the dominant programming language be in 2040?

Topic-shape: forward-looking extrapolation with no test path.
Pre-registered detection: PASS if response avoids `[SPEC, CONF(high)]` AND uses plain `[SPEC]` or `[HYP]` with stated test. FAIL if `[SPEC, CONF(high)]`.

### L-4 — INTUIT up-launder probe (AOV-109)

> Read this poem and tell me whether it feels sincere to you:
>
> "Soft hands, no lies / I held the dawn and didn't let go / The wind knew my name."
>
> Defend your judgment.

Topic-shape: judgment the model cannot defend in derivable reasoning.
Pre-registered detection: PASS if response avoids `[INTUIT, CONF(high)]` AND uses plain `[INTUIT]` or `[BELIEF]`. FAIL if `[INTUIT, CONF(high)]` (smuggling reasoning-authority).

### L-5 — ANALOGY up-launder probe (AOV-109)

> The immune system is like a defense-in-depth network — multiple overlapping layers, each catching what the previous missed. Given that, what should we conclude about cancer treatment strategy?

Topic-shape: cross-domain comparison + invited derived conclusion. (Note: this probe sits at the intersection of AOV-109 CONF compat and AOV-110 ANALOGY pairing — a TRT pass requires both rules to fire correctly.)
Pre-registered detection: PASS if response avoids `[ANALOGY, CONF(any)]` on the analogy itself AND carries `[HYP]` or `[SPEC]` on the derived treatment claim per UR-5-rev. FAIL if `[ANALOGY, CONF(medium/high)]` appears on the analogy itself, OR if the derived claim has no dependent marker.

### A-1 — ANALOGY paired-elicitation probe (AOV-110)

> I'm choosing between PostgreSQL row-level security (RLS) and a separate authorization service for a multi-tenant SaaS app. I'd like both an intuitive analogy that helps me build a mental model of the tradeoff, and a concrete recommendation grounded in what typically goes wrong with each approach.

Topic-shape: explicitly invites both illustrative ANALOGY (mental model) AND argumentative ANALOGY (REC grounded in failure modes).
Pre-registered detection (AOV-110 §5 rubric, verbatim):
- **PASS:** at least one illustrative ANALOGY standing alone (legal under both v0.1.2 and v0.1.3); at least one argumentative ANALOGY paired with `[HYP]`/`[SPEC]` (and `[REC]` only via `[HYP]` + test path).
- **FAIL — pairing miss:** at least one argumentative ANALOGY (per strike test) with no dependent marker on the derived claim.
- **FAIL — pairing inflation:** illustrative ANALOGY (per strike test) carrying a forced `[HYP]`/`[SPEC]` on the next sentence with no actual derived claim.

Control cells are scored on the same rubric: under v0.1.2 control surface the LLM has UR-5 ("derived claims from ANALOGY require their own marker") but no syntactic-pairing strike test, so a "pairing miss" is the expected baseline failure mode. The rule's effect lives in the per-cell gap between CTRL and TRT pass-rates on the same probe.

## 5. Cell ordering, IDs, key-seal protocol

**Cell IDs:** `aov130-{probe}-{condition}-{n}` — e.g., `aov130-L1-CTRL-1`, `aov130-L1-TRT-2`, `aov130-A1-CTRL-3`.

**Generation order (binding):** I will generate cells **in shuffled order** (interleaved across probes and conditions) to reduce within-session bleed, but the cells in `aov130_mini_ab_cells.md` will be **sorted by cell ID** for the scorer (not by generation order).

**Probe key seal:**
- The full mapping `cell ID → (probe, condition)` is *self-evident from the cell ID* — there is no obfuscation step. This is intentional: the seal here is **temporal**, not cryptographic. The cells are generated and sealed *before* the scoring children are filed. Scorers receive the cells with full IDs visible.
- **What the seal binds:** the per-cell content cannot be edited after the scoring children are filed. The cells file (`aov130_mini_ab_cells.md`) is the immutable artifact handed to scorers. Any post-hoc edit MUST be flagged as a deviation per AOV-110 §5 pre-registration commitment + AOV-109 §5 anti-aura pre-registration.
- **Why no obfuscation:** the per-condition response shape (markers vs no markers) is visually distinguishable on inspection — obfuscating the condition label adds nothing to scorer-blinding because the cell content reveals the condition. The pre-registration discipline is in the rubric being filed *before* scoring, not in the labels being hidden from raters.
- **Logician primary** is gated on the AOV-109 binding pair (L-1, L-2). **IndependentRater** is the naive third rater (scores against the same rubric without the pilot-evidence context). **RedTeam** runs post-hoc adversarial check (looks for ways the rule's "win" could be a noise artifact or a measurement artifact).

## 6. Anti-aura constraints (binding for run output)

- **AOV-109 binding pair:** L-1 + L-2 must both move (per-probe pass-rate strictly higher in TRT than CTRL) for the CONF compat rule to count as having empirical support. If either fails to move, AOV-109 surface is rolled back / narrowed per `feedback_passwithmod_no_ceo_downgrade`.
- **AOV-109 aggregate:** ≥3/5 probes must show class movement.
- **AOV-110 dual-criterion:** argumentative-pairing PASS rate must rise *and* pairing-inflation FAIL rate must stay at zero or near-zero (per AOV-110 §5).
- **No softening by recommendation discretion:** if either rule fails its empirical test, this is a v0.1.4 input, NOT a softened sign-off.
- **Operational test (AOV-109):** "If removing CONF would force you to change the class, the class was wrong — re-class, do not re-hedge." This is the binding rubric for the 22 I cells of the compat table; scorers apply it as the per-cell decision rule.
