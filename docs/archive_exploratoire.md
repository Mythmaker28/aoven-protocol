# Archive exploratoire (pré-protocole)

**Status:** [validated] under decision D4 (archived; not canon). Corrected v0.1.2 historical descriptions per D9.

This file documents seven terms (Aoa, Aova, Orven, Renavé, Renavé-mu, Renavé-li, Renavé-zo) that come from an earlier conlang phase predating the Aoven protocol. **None is part of the protocol's 14-marker set.** They are documented here for historical traceability and to make the archive verdict (D4) reviewable.

*Verdict source: CTO draft, AOV-7, 2026-04-26. Renavé family origin source: board input on AOV-15, applied via AOV-16 (v0.1.2 correction, D9).*

## Reuse rule

These terms may be reintroduced into the protocol surface **only if** an agent demonstrates that the term serves a unique epistemic function not already covered by one of the 14 markers (FACT, HYP, INTUIT, ANALOGY, BELIEF, EMOTION, MEMORY, INTERPRET, UNCERTAIN, NOSRC, CONF, REC, SPEC, LIMIT). **Burden of proof is on retention.** Until such a demonstration is filed and audited, status remains `[observation]` and the term is not canon.

This rule embodies project constraint **C-2 (anti-aura)** in `AGENTS.md`: Aoven is an engineering artifact for reducing slippage in LLM output, not a fantasy conlang or poetic dictionary.

## Why the v0.1.2 correction matters

Earlier project text asserted that Renavé-mu / li / zo were confidence gradients superseded by `CONF(high/medium/low)`. No agent had a source for the original meaning of these terms; the assertion was confident, plausible, and wrong. The board supplied the correct origin on AOV-15. The fabrication is logged in D9 of the canonical spec — not silently overwritten — because the slippage class (confident assertion without source) is precisely the failure mode the Aoven protocol is built to prevent. This archive entry, together with D9 and project constraint C-6 ("no invented history"), is the standing reminder.
